# Week 5: filtered vector search in Cassandra

Companion files for the
[week 5 post](https://8567.me/posts/c5-cmovie-wk05-filtered-vector-search/) of the
cMovie series on [8567.me](https://8567.me). The series teaches Apache
Cassandra® 5.0 features by building movie search for a fictional app called
cMovie, running on Astra DB.

This week you add ordinary `WHERE` clauses to an `ORDER BY ... ANN OF` query,
so a search for meaning can also say "and it must be science fiction". There
is no schema change and no new index this week, so there's no `schema.cql`.

## Files

| File | What it is |
| --- | --- |
| [`queries.cql`](queries.cql) | The post's statements: genre, decade and rating filters, a narrow filter against `LIMIT`, and the filter on an unindexed column that Cassandra rejects |

`queries.cql` is a reference copy to paste into the Astra CQL console, one
statement at a time. It isn't a script to run as a whole, and it doesn't create
a keyspace. Run `USE default_keyspace;` first, as the post explains.

## What you need

- The `movies` table from weeks 1 to 3, with every movie's `plot_embedding`
  filled in and the vector index from week 3's
  [`schema.cql`](../week-03/schema.cql) built.
- `GEMINI_API_KEY` in your `.env` file. The setup page covers it in
  [section 3](../../docs/setup.md#3-google-ai-studio).

Each `ANN OF` statement needs the phrase as a vector, which the console can't
make. From the root of the repo, in your virtual environment, let the helper
write the complete statement, then paste it into the console:

```bash
python tools/embed_query.py "a lonely robot learns what love is" --limit 10 \
  --where "genres CONTAINS 'science fiction'"
```

Each run sends your phrase to Google's Gemini API, which counts as one text
against your free tier allowance. Embed the phrase once, then edit the `WHERE`
clause of the statement you already have.

The setup page covers the database, token and loader:
[`docs/setup.md`](../../docs/setup.md).

## Data and licences

Film facts come from [Wikidata](https://www.wikidata.org), released under
[CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/). Plot text comes
from the [English Wikipedia](https://en.wikipedia.org), released under
[CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/). The queries
return titles, years, genres and ratings, and never the plot text. The
`cmovie_rating`, `cmovie_votes` and `cmovie_popularity` columns are fictional
numbers generated by the loader, not real audience scores.

Search phrases are sent to Google's Gemini API to create the query embeddings.
Google's terms for the free tier allow it to use what you send to improve its
products and to let human reviewers read it, so only type phrases you'd be
happy for Google to see.
